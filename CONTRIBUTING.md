# Contributing

The Accessible Components Library is maintained by [TetraLogical](https://tetralogical.com/), and we welcome you telling us when something is wrong, or suggesting what could be better.

By taking part you agree to follow our [code of conduct](CODE_OF_CONDUCT.md).

## Reporting a problem

If a component has a problem, or the documentation is wrong, [open an issue](https://github.com/TetraLogical/accessible-components-library/issues/new/choose), and let us know:

- Which component and variant
- What you expected to happen, and what actually happened
- Which browser, operating system, and assistive technology you were using, and their versions

We investigate any accessibility problems as bugs, and we want this library to be as useful as possible. So, please don't hold back a report just because an issue feels minor.

## Reporting a security problem

If you think you've found a security problem, don't open an issue, because anyone can read it. Follow our [security policy](SECURITY.md) to report it privately instead.

## Suggesting an improvement

If you think we're missing a component or variant, a test scenario, or you think theres a better way something could work, [open an issue](https://github.com/TetraLogical/accessible-components-library/issues/new/choose). Describe what you think is missing, who it helps, or anything else that might be useful, like WCAG criteria or links to similar components.

## We're not accepting pull requests yet

For now, we're not accepting pull requests. We might in future, but for now, any that are opened will be automatically closed without being merged.

The library is new, and we're still figuring things out. Each component carries a full set of accessibility requirements and test scenarios that have to stay perfectly in sync with the code and any manual testing, so we're keeping changes in-house for now.

That doesn't mean we don't want your input. Bug reports and suggestions are still welcome, we will read every issue.

## Decisions and transparency

We will review every issue and decide what to do with it. But, we can't promise we'll implement every single one. Some may not fit into the scope of the library, and some may have to wait until we have the capacity to take it on.

Whatever we decide to do with an issue, we'll try to be as transparent as possible. If we're not going ahead with it, we'll close it out with a clear reason why.

## Using the code for your own projects

The library is released under the [ISC licence](LICENSE), so you're free to fork it and adapt it for your own design system or projects, as long as you reference the copyright notice. [The development guide](DEVELOPMENT.md) explains how the repository is put together, how to build and test it, and how to add a component, in case you want to keep to the same structure.
